# Voryx Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Painel SaaS multi-usuário para operar grupos de prévias no Telegram: conectar contas (MTProto), agendar posts por conta, aprovar solicitações de entrada (auto/manual), remover/banir membros e detectar contas caídas.

**Architecture:** Um único processo Python (FastAPI + todos os clientes Telethon no mesmo event loop asyncio) com Postgres como banco e fila (`jobs`). Todo acesso ao Telegram passa pela interface `TelegramGateway`; os testes usam `FakeGateway`. Frontend Next.js na Vercel fala com `api.voryx.pro` por cookie first-party.

**Tech Stack:** Python 3.12, FastAPI, Telethon 1.x, SQLAlchemy 2 async (asyncpg / aiosqlite nos testes), Alembic, Pydantic v2 + pydantic-settings, argon2-cffi, cryptography (Fernet), itsdangerous, pytest + pytest-asyncio + httpx; Next.js 15 (App Router) + TypeScript + Tailwind; PostgreSQL 16; Docker Compose; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-03-voryx-design.md`

## Global Constraints

- Nome do produto: **Voryx** em código, UI, containers, env vars (`VORYX_*`).
- UI em PT-BR; horários exibidos em `America/Sao_Paulo`; banco sempre em UTC (datetimes tz-aware).
- Tema: fundo `#0B0B0C`, superfície `#151517`, dourado `#C9A54C`, texto off-white `#F5F3EE`; vermelho só para `dead`/erro; verde discreto para `online`.
- Sem Redis/ARQ, sem filas externas, sem microserviços. Containers: `app` (`mem_limit: 1g`) e `postgres` (`mem_limit: 512m`).
- `session_enc` e `api_hash_enc` nunca aparecem em resposta de API nem em log. Senha 2FA nunca persistida.
- Toda rota de parceiro filtra por `owner_id`; recurso de outro dono → **404** (nunca 403). Admin vê tudo.
- Escrita (POST/PATCH/PUT/DELETE) exige header `X-Voryx-CSRF: 1`, senão 403.
- Erros fatais de conta (→ `dead`, sem retry): `AuthKeyUnregisteredError`, `UserDeactivatedError`, `UserDeactivatedBanError`, `SessionRevokedError`, `AuthKeyDuplicatedError`.
- Throttle de aprovação: 1 a cada 2–4 s por conta, máx. 300/hora por conta.
- `FloodWaitError(s)` → reagenda em `now + s + 5`, não conta tentativa. Transitório → até 3 tentativas com backoff (30s, 120s, 600s).
- Texto de post ≤ 4096; com mídia ≤ 1024; 0–10 mídias; arquivo ≤ `VORYX_MAX_UPLOAD_MB` (padrão 500).
- Mídia em `/data/media/{owner_id}/{uuid}`; apagada 7 dias após `sent`/`canceled`.
- Login pendente expira em 10 min. Health check a cada 10 min; sync de grupos a cada 30 min; poll de solicitações a cada 2 min; executor a cada 3 s.
- Login do painel: máx. 10 tentativas / 15 min por IP. Cookie `voryx_session`: httpOnly, Secure, SameSite=Lax, `Domain=.voryx.pro` (configurável; vazio em dev).
- VPS: pasta `/opt/voryx`; deploy `cd /opt/voryx && git pull --ff-only && docker compose up -d --build app`.
- Não implementar: reações/respostas automáticas encadeadas entre contas, proxy por conta, posts recorrentes, cobrança, cadastro aberto, integração automática TData.

## Review Focus

1. **IDOR entre parceiros** — parceiro B chamando qualquer endpoint com ID de conta/grupo/post/mídia/solicitação do parceiro A deve receber 404 e nada mudar. Teste parametrizado em Task 12.
2. **Restart com post em `sending`** — ao iniciar, posts em `sending` viram `failed` com erro `"interrompido durante o envio — verificar no grupo"` e não são reenviados. Teste em Task 10.
3. **Agendar no passado / fuso** — usuário envia `2026-11-10T20:00:00-03:00` → salvo `23:00Z`; `run_at` mais de 60 s no passado sem `post_now` → 422. Teste em Task 10.
4. **Conta cai com jobs na fila** — jobs de conta `dead` falham na hora com `"conta caída"`, sem chamar o gateway; grupo cuja conta gestora morreu mostra `conta_caida` e o poll de solicitações o ignora. Testes em Tasks 6 e 8.
5. **Upload grande / legenda longa** — arquivo acima do limite → 413 sem gravar o arquivo inteiro em memória (streaming em chunks); post com mídia e texto de 1025 caracteres → 422. Testes em Task 10.
